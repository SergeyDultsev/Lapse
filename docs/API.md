# Lapse API

Документация по REST API backend'а (NestJS + TypeORM + PostgreSQL).

- **Базовый URL:** `http://localhost:3000` (порт задаётся через `PORT`)
- **CORS:** разрешён origin `http://localhost:5000`, запросы с credentials

## Общие правила

### Аутентификация

Токены передаются **не в заголовке**, а через httpOnly-cookie:

| Cookie | Назначение | Живёт |
|---|---|---|
| `accessToken` | основной токен, проверяется `JwtGuard` | 15 мин (по умолчанию) |
| `refreshToken` | обновление пары, проверяется `JwtRefreshGuard` | 7 дней (по умолчанию) |

Клиент должен отправлять запросы с `credentials: 'include'` (fetch/axios), иначе куки не прикрепятся.

Три режима доступа к роутам:

- **🔒 auth** — обязателен валидный `accessToken`, иначе `401`
- **🔓 optional** — токен необязателен; если `accessToken` валиден, в ответе будет персональные данные (например `isLiked`), иначе значения по умолчанию
- **🌐 public** — без авторизации

### Формат ответа

Все ответы (включая ошибки) имеют единую обёртку:

```json
{
  "data": { },
  "message": "Comment created",
  "statusCode": 201
}
```

При ошибке `data` всегда `null`, `message` — текст или массив текстов ошибок валидации.

### Валидация

Глобальный `ValidationPipe` (`whitelist: true, transform: true`):

- неизвестные поля в body молча отбрасываются
- невалидные данные → `400` с массивом сообщений в `message`
- query-параметры приводятся к нужным типам

### Пагинация

Пагинированные списки принимают query-параметры:

| Параметр | По умолчанию | Правила |
|---|---|---|
| `page` | `1` | целое ≥ 1 |
| `limit` | `20` | целое 1–100 |

Мета пагинации возвращается рядом с коллекцией:

```json
"meta": { "totalItems": 42, "page": 1, "limit": 20, "lastPage": 3 }
```

## Auth — `/auth`

### `POST /auth/login` 🌐

Вход. Устанавливает обе cookie.

**Body:**

```json
{ "email": "user@mail.com", "password": "12345678" }
```

- `email` — валидный email
- `password` — строка от 8 символов

**Ответ `200`:** `data` — профиль пользователя (см. формат User ниже).

**Ошибки:** `401` — неверный email или пароль.

### `POST /auth/register` 🌐

Регистрация. Устанавливает обе cookie (пользователь сразу залогинен).

**Body:**

```json
{
  "username": "ivan",
  "email": "user@mail.com",
  "password": "12345678",
  "repeatPassword": "12345678"
}
```

- `username` — непустая строка, уникальная
- `password` и `repeatPassword` — совпадают, от 8 символов

**Ответ `201`:** `data` — профиль пользователя.

**Ошибки:** `409` — email или username уже занят.

### `POST /auth/logout` 🔒(refresh)

Выход. Требует валидный `refreshToken`-cookie (проверяется по хэшу в БД). Инвалидирует refresh-токен и очищает обе cookie.

**Ответ `200`:** `data: {}`.

### `GET /auth/me` 🔒

Профиль текущего пользователя.

**Ответ `200`:** `data` — профиль пользователя.

**Ошибки:** `401` — токен невалиден/просрочен; `404` — пользователь удалён.

### `POST /auth/refresh` 🔒(refresh)

Ротация токенов. Требует валидный `refreshToken`-cookie; старый refresh-токен инвалидируется, выдаётся новая пара в cookie.

**Ответ `200`:** `data: {}`.

**Ошибки:** `401` — refresh-токен отсутствует, просрочен или не совпал с хэшем в БД.

## Users — `/users`

### `GET /users/:id` 🌐

Профиль пользователя по id.

**Ошибки:** `404` — пользователь не найден.

### `GET /users` 🌐

Список всех пользователей.

**Ответ `200`:** `data` — массив профилей.

> ⚠️ Эндпоинт публичный и отдаёт список всех пользователей вместе с их email. Если это не нужно — стоит закрыть guard'ом или ограничить поля.

### Формат User

```json
{
  "userId": "uuid",
  "username": "ivan",
  "email": "user@mail.com",
  "bio": "",
  "meta": {
    "countFollowers": 0,
    "countSubscriptions": 0,
    "countPosts": 3,
    "createdAt": "2026-10-01T12:00:00.000Z",
    "updatedAt": "2026-10-01T12:00:00.000Z"
  }
}
```

Пароль и хэш refresh-токена наружу не отдаются.

## Posts — `/posts`

### `POST /posts/create` 🔒

Создание поста.

**Body:**

```json
{ "title": "Заголовок", "textContent": "Текст поста" }
```

**Ответ `201`:** `data` — созданный пост (формат Post ниже), `isLiked: false`.

### `GET /posts` 🔓

Все посты, от новых к старым.

**Ответ `200`:** `data` — массив постов с `isLiked` текущего пользователя (если передан токен).

### `GET /posts/:id` 🔓

Пост по id. **Каждый вызов засчитывает просмотр** (`countView` +1).

**Ответ `200`:** `data` — пост.

**Ошибки:** `404` — пост не найден.

### `GET /posts/users/:id` 🔓

Посты конкретного пользователя (пагинация: `?page=1&limit=20`).

**Ответ `200`:**

```json
{
  "posts": [ ... ],
  "meta": { "totalItems": 10, "page": 1, "limit": 20, "lastPage": 1 }
}
```

### `DELETE /posts/:id` 🔒

Удаление поста. Удалять может только автор.

**Ответ `200`:** `data` — удалённый пост.

**Ошибки:** `403` — не ваш пост; `404` — пост не найден.

### Формат Post

```json
{
  "postId": "uuid",
  "userId": "uuid",
  "title": "Заголовок",
  "textContent": "Текст",
  "isLiked": false,
  "meta": {
    "countLike": 5,
    "countComment": 2,
    "countView": 100,
    "createdAt": "2026-10-01T12:00:00.000Z",
    "updatedAt": "2026-10-01T12:00:00.000Z",
    "author": { ...User }
  }
}
```

## Comments — `/comment`

### `POST /comment/create/:postId` 🔒

Создание комментария к посту.

**Body:**

```json
{ "textContent": "Текст комментария", "parentCommentId": "uuid-optional" }
```

- `parentCommentId` — опционально; ответ на топ-комментарий

**Правила:**

- родительский комментарий должен существовать в этом же посте (`404`)
- ответы на ответы запрещены — максимальная глубина вложенности 1 (`400`)
- счётчики `countComment` поста и `countReplies` родителя обновляются автоматически

**Ответ `201`:** `data` — созданный комментарий, `isLiked: false`.

**Ошибки:** `404` — пост или родительский комментарий не найдены.

### `GET /comment/:postId` 🔓

Топ-уровневые комментарии поста (без ответов), от новых к старым. Пагинация: `?page=1&limit=20`.

**Ответ `200`:** `data.comments` + `data.meta` (как у постов).

### `GET /comment/:commentId/replies` 🔒

Ответы на комментарий, от старых к новым. Требует авторизацию.

**Ответ `200`:** `data` — массив ответов с `isLiked`.

### `DELETE /comment/:commentId` 🔒

Удаление комментария.

**Правила:**

- удалять может только автор (`403`)
- нельзя удалить комментарий, у которого есть ответы (`400`) — сначала удалите ответы
- счётчики `countComment` поста и `countReplies` родителя уменьшаются автоматически

**Ответ `200`:** `data: { "commentId": "uuid" }`.

### Формат Comment

```json
{
  "commentId": "uuid",
  "userId": "uuid",
  "postId": "uuid",
  "parentCommentId": "uuid | null",
  "textContent": "Текст",
  "isLiked": false,
  "meta": {
    "countLike": 3,
    "countReplies": 0,
    "createdAt": "2026-10-01T12:00:00.000Z",
    "updatedAt": "2026-10-01T12:00:00.000Z",
    "author": { ...User }
  }
}
```

## Post likes — `/post-like`

### `POST /post-like/toggle` 🔒

Переключение лайка поста (лайкнут → снять, нет → поставить).

**Body:**

```json
{ "postId": "uuid" }
```

**Ответ `200`:** `data` — пост с актуальными `isLiked` и `meta.countLike`; `message`: `"Like created"` или `"Like removed"`.

**Ошибки:** `404` — пост не найден.

### `POST /post-like/favorite` 🔒

Посты, лайкнутые текущим пользователем, от новых лайков к старым.

**Ответ `200`:** `data` — массив постов (все с `isLiked: true`).

---

## Comment likes — `/comment-like`

### `POST /comment-like/toggle` 🔒

Переключение лайка комментария.

**Body:**

```json
{ "commentId": "uuid" }
```

**Ответ `200`:** `data` — комментарий с актуальными `isLiked` и `meta.countLike`; `message`: `"Like created"` или `"Like removed"`.

**Ошибки:** `404` — комментарий не найден.

## Коды ошибок

| Код | Когда |
|---|---|
| `400` | ошибки валидации body/query; бизнес-правила (ответ на ответ, удаление комментария с ответами) |
| `401` | нет/просрочен/невалиден `accessToken`; невалиден `refreshToken` |
| `403` | действие чужого ресурса (удаление чужого поста/комментария) |
| `404` | сущность не найдена |
| `409` | конфликт при регистрации (email/username занят) |
| `500` | необработанная ошибка (логируется на сервере) |

## Замечания по безопасности (на будущее)

1. `GET /users` отдаёт всех пользователей с email без авторизации — стоит закрыть или сократить поля.
2. `POST /post-like/favorite` логичнее сделать `GET`.
3. Лайки защищены unique-индексом `(userId, postId/commentId)` — дубли из гонок запросов исключены, но сам toggle не транзакционен: при одновременных запросах возможен race между проверкой и вставкой (уникальный индекс не даст вставить дубль — запрос упадёт с 500; идеально — upsert/транзакция).
